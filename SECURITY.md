# Security Policy

## Supported version

Security fixes are applied to the current `main` branch. Historical contracts and
release archives are retained for provenance and are not separate supported
release lines.

## Reporting a vulnerability

Report suspected vulnerabilities privately through the repository's
[GitHub private vulnerability reporting form][report]. Do not open a public
issue, pull request, or discussion for an unpatched vulnerability.

Include the affected file or revision, reproduction steps, expected impact, and
the smallest safe proof of concept needed to verify the report. Avoid including
credentials, personal data, unpublished source material, licensed PDFs, private
audit bundles, prompts, or other sensitive evidence unless the maintainers
explicitly request it through a private channel. Redact secrets and use synthetic
samples whenever possible.

Please allow the maintainers time to reproduce and remediate the issue before
public disclosure. If the private reporting form is unavailable, contact the
repository owner through a private GitHub channel without attaching sensitive
materials.

[report]: https://github.com/hoiyu915-droid/EvidenceProse/security/advisories/new
